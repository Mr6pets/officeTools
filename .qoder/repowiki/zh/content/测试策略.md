## 测试目录结构

## 组件测试最佳实践

尽管当前项目无测试，但基于 `Calculator.tsx` 组件的实现，可制定以下组件测试最佳实践：

### 1. 单元测试目标
- 验证单位转换逻辑的正确性（长度、重量、温度）
- 验证个税计算公式的准确性
- 验证房贷计算的数学逻辑
- 验证用户输入验证（如非数字输入处理）

### 2. 使用 React Testing Library
推荐使用 `@testing-library/react` 进行组件测试，因其鼓励以用户行为为导向的测试方式。

### 3. 示例测试代码
```tsx
// tests/unit/components/Calculator.test.tsx
import { render, screen, fireEvent } from '@testing-library/react';
import Calculator from '../../../src/components/Calculator';

describe('Calculator Component', () => {
  test('长度单位转换功能正常', () => {
    render(<Calculator />);
    
    // 选择长度转换
    fireEvent.click(screen.getByText('长度'));
    
    // 输入数值
    const input = screen.getByPlaceholderText('输入数值');
    fireEvent.change(input, { target: { value: '1' } });
    
    // 选择从米到厘米
    fireEvent.change(screen.getByTestId('from-unit'), { target: { value: 'm' } });
    fireEvent.change(screen.getByTestId('to-unit'), { target: { value: 'cm' } });
    
    // 点击转换
    fireEvent.click(screen.getByRole('button', { name: '计算' }));
    
    // 验证结果
    expect(screen.getByText('转换结果: 100 厘米')).toBeInTheDocument();
  });

  test('温度转换功能正常', () => {
    render(<Calculator />);
    
    fireEvent.click(screen.getByText('温度'));
    fireEvent.change(screen.getByPlaceholderText('输入数值'), { target: { value: '0' } });
    fireEvent.change(screen.getByTestId('from-unit'), { target: { value: 'c' } });
    fireEvent.change(screen.getByTestId('to-unit'), { target: { value: 'f' } });
    fireEvent.click(screen.getByRole('button', { name: '计算' }));
    
    expect(screen.getByText('转换结果: 32 华氏度')).toBeInTheDocument();
  });
});
```

### 4. 测试异步逻辑
对于包含异步操作的组件（如 `RegexTester.tsx` 中的防抖测试），应使用 `waitFor` 或 `async/await` 进行测试。

## API测试最佳实践

基于 `backend/server.js` 中的路由实现，可制定以下API测试最佳实践：

### 1. 测试覆盖的路由
- `POST /api/register`：用户注册
- `POST /api/login`：用户登录
- `GET /api/users`：获取用户列表

### 2. 使用 Supertest 进行测试
推荐使用 `supertest` 库对 Express 应用进行HTTP请求测试。

### 3. 模拟数据库
使用 `jest.mock()` 或 `sqlite3` 内存数据库来模拟 `better-sqlite3`，避免测试污染真实数据。

### 4. 示例测试代码
```js
// tests/integration/api/server.test.js
const request = require('supertest');
const app = require('../../../backend/server');

describe('User API', () => {
  let server;

  beforeAll(() => {
    server = app.listen(3001);
  });

  afterAll((done) => {
    server.close(done);
  });

  describe('POST /api/register', () => {
    test('成功注册新用户', async () => {
      const response = await request(server)
        .post('/api/register')
        .send({
          username: 'testuser',
          email: 'test@example.com',
          password: 'password123'
        });

      expect(response.statusCode).toBe(200);
      expect(response.body.success).toBe(true);
      expect(response.body.message).toBe('注册成功');
    });

    test('注册已存在用户应返回400', async () => {
      // 先注册一次
      await request(server)
        .post('/api/register')
        .send({
          username: 'existuser',
          email: 'exist@example.com',
          password: 'password123'
        });

      // 再次注册相同用户
      const response = await request(server)
        .post('/api/register')
        .send({
          username: 'existuser',
          email: 'exist@example.com',
          password: 'password123'
        });

      expect(response.statusCode).toBe(400);
      expect(response.body.success).toBe(false);
    });
  });

  describe('POST /api/login', () => {
    test('正确凭据应成功登录', async () => {
      // 先注册
      await request(server)
        .post('/api/register')
        .send({
          username: 'loginuser',
          email: 'login@example.com',
          password: 'password123'
        });

      // 登录
      const response = await request(server)
        .post('/api/login')
        .send({
          username: 'loginuser',
          password: 'password123'
        });

      expect(response.statusCode).toBe(200);
      expect(response.body.success).toBe(true);
    });
  });
});
```

## 运行测试与报告查看

由于当前项目无测试，需先引入测试框架。建议方案如下：

### 1. 安装测试依赖
```bash
# 前端测试
npm install --save-dev jest @testing-library/react @testing-library/jest-dom jsdom

# 后端测试
npm install --save-dev jest supertest --prefix backend
```

### 2. 配置测试脚本
在根目录 `package.json` 中添加：
```json
"scripts": {
  "test": "jest",
  "test:watch": "jest --watch",
  "test:coverage": "jest --coverage"
}
```

在 `backend/package.json` 中添加：
```json
"scripts": {
  "test": "jest",
  "test:api": "jest --watch ./tests/integration/api/"
}
```

### 3. 运行测试
```bash
# 运行所有测试
npm test

# 生成覆盖率报告
npm run test:coverage
```

报告将生成在 `coverage/` 目录下，包含 HTML 可视化报告。

## 持续集成（CI）集成

建议在项目中引入 GitHub Actions 实现持续集成。

### 1. 创建 CI 配置文件
```yaml
# .github/workflows/test.yml
name: Test

on: [push, pull_request]

jobs:
  test:
    runs-on: ubuntu-latest
    
    steps:
      - uses: actions/checkout@v3
      
      - name: Setup Node.js
        uses: actions/setup-node@v3
        with:
          node-version: 18
      
      - name: Install dependencies
        run: npm ci
      
      - name: Install backend dependencies
        run: npm ci
        working-directory: ./backend
      
      - name: Run tests
        run: npm test -- --coverage
      
      - name: Upload coverage to Codecov
        uses: codecov/codecov-action@v3
```

### 2. CI 流程
- 每次推送或 PR 时自动运行测试
- 生成测试覆盖率报告并上传至 Codecov
- 测试失败则阻止合并
